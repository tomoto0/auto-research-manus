# Auto Research Manus Integration Verification

This document records the concrete wiring evidence used before final testing and checkpoint creation. It is intended to make the Manus Platform integration auditable without changing the existing UI or core pipeline logic.

| Area | Verification | Evidence |
|---|---|---|
| tRPC router registration | The cloned repository routers are mounted in the final `appRouter`. | `server/routers.ts` registers `pipeline`, `literature`, `settings`, `artifacts`, and `datasets` alongside `system` and `auth`. |
| Protected backend operations | Pipeline execution, run management, literature search, settings, artifacts, datasets, and upload procedures are protected. | `server/routers.ts` uses `protectedProcedure` for `pipeline.start`, `stop`, `approve`, `reject`, `approvalStatus`, `get`, `list`, `events`, `literature.search`, `literature.forRun`, `settings`, `artifacts`, and `datasets`. `server/upload-procedures.ts` exports `uploadChunkProcedure`, `assembleChunksProcedure`, and `registerFileProcedure` as `protectedProcedure`. |
| Intentionally public procedures | Only non-sensitive metadata and session helpers remain public. | `pipeline.stages`, `pipeline.templates`, `auth.me`, and `auth.logout` remain `publicProcedure`; these expose static pipeline metadata or current-session/logout behavior and do not start research jobs or access user artifacts. |
| Frontend auth flow | Existing pages/components use the Manus auth hooks without redesign. | `client/src/pages/Home.tsx` imports `useAuth` and `getLoginUrl`; `client/src/components/DashboardLayout.tsx` uses `useAuth`, `logout`, and `getLoginUrl`. |
| LLM server-side isolation | Research AI calls remain server-side only. | `server/pipeline-engine.ts` and `server/experiment-runner.ts` import `invokeLLM` from `server/_core/llm.ts`; the client has no `invokeLLM` calls. A frontend scan found only a comment in `AIChatBox.tsx`, not an invocation. |
| Literature pipeline | Literature search is invoked through the server router and pipeline engine. | `server/routers.ts` imports `unifiedSearch` from `server/literature.ts` for `literature.search`; `server/pipeline-engine.ts` imports and calls `unifiedSearch` during the pipeline. |
| Experiment execution | Experiment runner is invoked by the pipeline and covered by tests. | `server/pipeline-engine.ts` imports `executePythonExperiment` from `server/experiment-runner.ts` and calls it during experiment execution. Existing tests import and validate `executePythonExperiment`. |
| Worker integration | Worker mode is preserved from the cloned app. | `server/worker.ts` imports `executePipeline` from `server/pipeline-engine.ts`; `package.json` contains `dev:worker`, `start:worker`, `dev:api`, and `start:api` scripts controlled by `PIPELINE_EXECUTION_MODE`. |
| File storage | Storage helpers are used for uploads, generated charts, tables, papers, PDFs, and error artifacts. | `server/upload-procedures.ts`, `server/experiment-runner.ts`, and `server/pipeline-engine.ts` call `storagePut`; `server/storage.ts` uses Manus built-in Forge credentials. |
| DTA parser | The DTA parser is wired into uploads and experiment parsing. | `server/upload-procedures.ts` imports `parseDtaFile` dynamically for `.dta` previews; `server/experiment-runner.ts` imports `parseDtaFileAsync` for `.dta` analysis; `server/pipeline.test.ts` includes DTA parser tests. |
| PDF generation | PDF generation is server-side and artifact-backed. | `server/pipeline-engine.ts` imports `generatePaperPdf` from `server/pdf-generator.ts`, uploads generated PDFs with `storagePut`, and records `paper_pdf` artifacts. |
| Owner notifications | Notifications are hooked into key pipeline events. | `server/pipeline-engine.ts` calls `notifyOwner` through `notifyPipelineOwner` for PDF report generation, experiment completion, pipeline completion, and pipeline errors. |
| Runtime configuration | No committed secrets are required; platform envs are referenced at runtime. | `server/_core/env.ts`, `server/storage.ts`, `server/_core/llm.ts`, `drizzle.config.ts`, and package scripts use `DATABASE_URL`, `JWT_SECRET`, OAuth envs, `BUILT_IN_FORGE_API_URL`, `BUILT_IN_FORGE_API_KEY`, and `PIPELINE_EXECUTION_MODE`. |

The only frontend reference to `VITE_FRONTEND_FORGE_*` detected is the prebuilt Google Maps proxy component, which is unrelated to the research LLM flow and is part of the Manus template capability. No client-side LLM invocation or server-side secret exposure was found during the audit.
